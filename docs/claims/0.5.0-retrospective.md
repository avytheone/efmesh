## 4. Additive claim and what the trial catches

New wire fields preserve the old keys for tolerant readers; the browser accepts
an omitted `effective`. That is a bounded additive-wire argument, not a claim
about every consumer. `passportOf` also changes existing returned limits to use
DAG-effective values when available (`src/browser/index.ts`); behavior is not
unchanged merely because keys remain.

**The blanket source-additive claim is false.** Newly required exported fields
are `Audit.scope` (`src/core/audit.ts`), `Plan.warnings`
(`src/plan/planner.ts`), `AuditRunReport.skipped` (`src/plan/audit-run.ts`), and
`Manifest.effective` (`src/plan/manifest.ts`). Old object literals satisfying the
old interfaces lack those fields. Builders supplying defaults do not repair
hand-built objects. This is a declaration-level finding, not an executed tsc
compatibility test. Historical CLI fixtures use `as never`; the export golden
checks names, not assignability of old consumer objects.

Auditing this sheet would have demanded a BREAKING/migration note for those
constructors (supply scope, warnings, skipped and effective as appropriate), or
a compatibility decision, before calling the release additive. The minor number
is allowed by policy; the missing qualification is the finding. This sheet does
not rewrite the historical CHANGELOG or repair runtime behavior.

## 5. Learned while testing

No historical tests were written or run for this retrospective, so no new
runtime lesson is claimed. **Recorded historical lesson:** the audit-scope
fixture pins `batchSize: 1` and explains that a wider rendered batch changes
what the interval pass sees (#54). The later-in-range window-warning commit
addresses that risk. **New source-review lesson:** additive JSON and stable
export names did not establish source compatibility of required public fields.

## 6. First diagnosis if this breaks

For an upgrade type error, compare the failing object to the four declarations
above before changing casts. For a wrong audit verdict, inspect scope,
`batchSize`, and the relation selected by `runAudits` in `src/plan/executor.ts`;
check whether the standalone report says the audit was skipped. For a freshness
claim, compare `efmesh passport <env> --json` declared/effective values and the
manifest ledger with `passportOf`'s fallback in `src/browser/index.ts`. Preserve
the exact binary/commit and failing fixture before interpreting later CI.
